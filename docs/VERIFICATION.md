# Alpha verification

## Executed locally

- Baseline: 67 Node tests passed, with zero failures or skips, on Node 26.5.0 on macOS. See the script-reuse validation below for the expanded suite.
- Tests cover retrieval freshness, actual spawned CLI commands, install/upgrade/uninstall/reinstall, preserved unrelated files, symlink and traversal rejection, replay identity, managed updates, rollback, archive/restore, injected write/move failures, and bounded state writes.
- An installed bundled CLI executed from an account path containing a space.

## Bootstrap-aware agent probe

An isolated Aside worker was given a synthetic recurring stock-report task and told to follow its workspace AGENTS guidance. It was not separately asked to save a skill.

The worker:

1. Produced a report accounting for four synthetic input rows.
2. Excluded an invalid row rather than clamping its availability, and marked the affected subtotal partial.
3. Verified the report and preserved the input.
4. Created a generalized managed Markdown procedure through the installed aftercare instructions.

A separate read confirmed the generated skill in the registry and catalog. A guarded load matched its current content hash with zero catalog diagnostics. Upgrading that isolated installation to the final payload preserved the learned skill, and doctor passed.

The probe used no real account data, private histories, credentials, or external actions. Its workspace, raw logs, and session identifiers are not included in this repository.

## Limits of this evidence

- This proves one bootstrap-aware synthetic workflow, not universal learning quality or guaranteed automatic use in every task.
- Normal fresh root-chat bootstrap loading remains unverified.
- The Node 20/22 Linux checks are defined in GitHub Actions; inspect the actual workflow run for their result rather than inferring it from the local test count.
- Privacy checks are heuristics. Caller attestations do not independently prove real-world outcomes.
- Crash recovery is fail-closed and requires reviewing local recovery state; it is not an automatically repaired background service.

## Script-reuse validation (2026-09-21 UTC)

- All 84 tests in the expanded Node suite passed locally with zero failures or skips. The suite covers whole-package history/rollback, script drift, reliability-before-cost selection, stale evidence, unknown-outcome blocking, task attempt limits, receipt conflicts, input serialization, and installed CLI execution.
- An isolated installation used the actual local Aside CLI to open and check the public Example Domain page. Two successful probes enabled reuse; a subsequent default execution succeeded. An intentionally false content check then failed and disabled default reuse. Only test-created tabs were closed.
- Provider usage was unavailable: receipts retain `tokens: null`. This is functional evidence, not a token-savings benchmark.
- In a separate bootstrap-aware synthetic task, the native Aside agent recorded the old stock-only recipe's failure on available-only input and saved a corrected MD/script package. A separate managed-package hash check and four local regression cases confirmed stock-only and available-only inputs succeed, while negative and conflicting quantities fail.
- That native-agent call timed out at the tool boundary before returning its final response. No final native success receipt was observed at artifact readback; this does not prove the complete native repair pipeline or automatic loading in ordinary fresh chats.
- All learning/install changes were inside isolated test account roots. The user's existing installed skill and built-ins were not upgraded. No private account data or browser results are included in public fixtures.
