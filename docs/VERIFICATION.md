# Alpha verification

## Executed locally

- Baseline: 67 Node tests passed, with zero failures or skips, on Node 26.5.0 on macOS. See the script-reuse validation below for the expanded suite.
- Tests cover retrieval freshness, actual spawned CLI commands, install/upgrade/uninstall/reinstall, preserved unrelated files, symlink and traversal rejection, replay identity, managed updates, rollback, archive/restore, injected write/move failures, and bounded state writes.
- An installed bundled CLI executed from an account path containing a space.

## Bootstrap-aware agent probe

An isolated Aside worker was given a synthetic recurring stock-report task and told to follow its workspace AGENTS guidance. It was not separately asked to save a skill.

The worker:

1. Produced a report accounting for four synthetic input rows.
2. Excluded an invalid row rather than clamping its availability, and marked the affected subtotal partial.
3. Verified the report and preserved the input.
4. Created a generalized managed Markdown procedure through the installed aftercare instructions.

A separate read confirmed the generated skill in the registry and catalog. A guarded load matched its current content hash with zero catalog diagnostics. Upgrading that isolated installation to the final payload preserved the learned skill, and doctor passed.

The probe used no real account data, private histories, credentials, or external actions. Its workspace, raw logs, and session identifiers are not included in this repository.

## Limits of this evidence

- This proves one bootstrap-aware synthetic workflow, not universal learning quality or guaranteed automatic use in every task.
- Initial testing did not verify normal fresh root-chat loading. The bounded live check below supersedes that result for directly selected managed skills only.
- The Node 20/22 Linux checks are defined in GitHub Actions; inspect the actual workflow run for their result rather than inferring it from the local test count.
- Privacy checks are heuristics. Caller attestations do not independently prove real-world outcomes.
- Crash recovery is fail-closed and requires reviewing local recovery state; it is not an automatically repaired background service.

- In a separate bootstrap-aware synthetic task, the native Aside agent recorded the old stock-only recipe's failure on available-only input and saved a corrected MD/script package. ## Fresh-chat automatic reuse (2026-09-21 UTC)

The initial CLI-created fresh session selected the relevant managed skill but skipped the coordinator and did not write an execution receipt. A subsequent normal saved chat loaded the coordinator but invented a double-prefixed skill name and a different context, then fell back to manual work. Both failed the automatic-reuse acceptance check despite returning correct page content.

The fix gives every generated managed skill a relative link back to the bootstrap. Executable skills also contain their exact registered route name and context. The bootstrap uses the already selected skill's exact name for discovery and tells callers to correct identifier errors before falling back.

With the fix installed, a fresh non-incognito, non-ephemeral, project-free Aside chat received only an ordinary public-page request: inspect example.com and report its title, notice, final URL, documentation-use statement, and operational-use warning. No skill name, bootstrap path, command, or execution hints were supplied in the task prompt. The trace showed automatic skill selection, bootstrap loading, route selection, attempt reservation, reading/hash-checking the saved script, native REPL execution, and a successful persisted receipt. The final page report matched the readback.

The candidate had two real read-only preparation probes; those were not counted as automatic-selection successes. Installation preserved the prior unmanaged prototype and original AGENTS file in a local backup, retained unrelated agent rules, and passed doctor. This host's actual user-skill installation was updated for this check; its account data, paths, transcripts, and session IDs are not published here.

This establishes one concrete discovery-and-reuse path, not universal routing, a global completion hook, or measured token savings. Model behavior can still vary. Doctor checks files and ownership, not session execution.

## Automatic MD repair after a changed input

A separate fresh saved session received only a synthetic recurring stock-report request: sum two `available` quantities and compare with expected. The prepared old recipe had passed two real stock-only probes but could not process the alternate field.

The session automatically selected the skill, entered the bootstrap, reserved the old recipe, observed failed verification, and recorded that attempt as failed. It used the MD rules to repair the procedure, checked the result, and updated the same managed task identity with a changed MD/script package. Independent readback verified the package hash changed and six regression cases: stock-only and available-only inputs succeed; negative, conflicting, missing, and overflowing quantities fail. The old failure remains a failure, and the new package starts unproven.

The agent initially made scratch-path and learning-record-shape mistakes, then corrected them without user intervention. Bootstrap guidance now explicitly creates scratch first and nests `context`/`effect` only inside `execution`. Recovery can cost additional model calls; these observations are not evidence of token savings.

For future work, a relevant read-only route marked `validation-needed` is checked against the MD and may receive one candidate probe for the current requested task. This collects evidence without running extra real tasks to meet the eligibility counter. Normal reuse still requires two recent successful observations for the exact version/context.

A subsequent fresh CLI session received a different available-only input, again without skill/command hints. It loaded the bootstrap automatically, observed `validation-needed`, reserved one `--probe`, executed the corrected recipe in native REPL, returned the correct total, and persisted a success for the new package hash. This was an ephemeral CLI session, distinguished from the earlier saved-chat reuse/repair checks. One new success does not yet meet the two-observation default-reuse gate.
